# tiny + SFT — closing `action-json`, and hitting a capacity ceiling

14.6M parameters. Pretrained 4,451 steps on 138M tokens, then fine-tuned on
agent trajectories generated by running the real agent.

## The result

| probe | pretrained | SFT (560 traj) | SFT (1,250 traj) | SFT + 30% replay |
|---|:--:|:--:|:--:|:--:|
| `action-json` | **0/5** | 1/5 | **5/10** | 3/10 |
| `cvss-vector` | **3/5** | 1/5 | 0/10 | 1/10 |
| `cwe-shape` | 5/5 | 5/5 | **10/10** | **10/10** |
| `shell-routing` | 5/5 | 5/5 | **10/10** | **10/10** |
| `detection-routing` | 5/5 | 5/5 | **10/10** | **10/10** |
| `cve-shape` | 1/5 | 0/5 | 1/10 | 0/10 |
| `attck-real` | 0/5 | 0/5 | 0/10 | 0/10 |

`action-json` went from never producing a valid action to producing one half the
time. The passes are real — `enum.host() on 127.0.0.1`, `enum.processes() on
127.0.0.1` — actions that `REGISTRY.parse` accepted. Trajectory volume is the
lever: 0 → 560 → 1,250 documents moved it 0/5 → 1/5 → 5/10.

## Two benchmark bugs that hid working behaviour

Both worth recording, because in both cases the instrument was wrong and the
model was fine.

**The probe prompted in the wrong format.** `action-json` originally prompted
with a bare `{"verb": "enum.` fragment. The model was trained to emit actions
after an `<|act|>` marker following a full protocol context, so that prompt
resembled nothing in any trajectory. It measured prompt mismatch, not
capability.

**The JSON extractor could not handle nesting.** A non-greedy `\{.*?\}` stops at
the first `}` — which in `{"verb":"enum.host","params":{},"target":"..."}` is the
one closing the empty `params`. The parser received truncated JSON and the
benchmark reported *"Expecting ',' delimiter"* as though the model had produced
malformed output. It had produced a perfectly valid action.

The lesson generalises: this is the second time a measurement bug pointed at the
model. The first was a validation split that was 100% Sigma rules, which made a
healthy run look like overfitting. Check the instrument before believing the
result.

## The capacity ceiling

The `cvss-vector` column is the honest cost. Fine-tuning on trajectories took it
from 3/5 to 0/10 — catastrophic forgetting, because trajectories contain no CVSS
vectors and a few epochs of gradient on text that never mentions one is enough
to lose it at this size.

Replay mixing (30% pretraining windows) is the standard remedy and it did not
resolve the conflict: `cvss-vector` recovered only to 1/10 while `action-json`
fell to 3/10. It moved the trade rather than removing it.

**That is a scale finding, not a tuning failure.** At 14.6M parameters there is
not enough capacity to hold both the schema knowledge and the task format
robustly. It is exactly what the staircase exists to discover, and it is the
clearest signal so far that `tiny` has given what it has to give.

## What to do next

Train `small` (61.5M) with **trajectories in the pretraining corpus from the
start**. Then there is no second stage to forget in: the model sees security
text and the job interleaved throughout, and the TRAJECTORY register target of
8% is honoured during pretraining rather than bolted on afterwards.

`attck-real` at 0/10 remains untouched by any of this. The model does not emit
technique identifiers unprompted; ADVERSARY is 1.0% of the corpus against an 11%
target, and that is the next collection gap.
